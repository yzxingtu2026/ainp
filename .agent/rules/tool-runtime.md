# Tool Runtime 硬约束

- 完整 ToolRegistry 只在服务端；模型固定工具为 `tool.search`、`tool.load`，核心工具仅在运行时资源条件满足时动态投影；禁止全量 Schema 或常驻 `tool.execute`。
- 模型调用通过 `enable_tools/tool_scope_id` 投影已加载真实 Schema，禁止客户端直接提交 `tools` 绕过 Registry。
- `tool.search` 的 source/capability 仅接受稳定代码精确过滤；Schema 必须声明 source 枚举与语义，Service 在 API/Agent Runtime 所有入口自行校验，非法过滤禁止静默空结果。
- Page Context hints 只能在 Registry/Scope/permission/realm/enabled 过滤后排序可见候选，禁止扩大 allowed scope、自动 load Schema 或绕过 Handle/确认/执行重鉴权。
- Tool ID 必须 namespaced；Provider/Executor 统一注册，未知来源、重复、非法 Schema 与缺失风险元数据 fail-closed。
- Tool Definition 分离稳定 `Name`/`DescriptionForLLM` 与插件自带 `TitleForHuman`/`DescriptionForHuman`；管理界面只展示 Human 契约，插件无需注册平台 i18n key，Human 文案不得进入 Schema Hash/Handle/Embedding 文档。
- Definition 必须显式声明 `binding_mode` 与 `loading_mode`；绑定组必须原子处理。Runtime 只投影 Contract 必选与用户可选有效绑定，禁止全局默认注入 Meta/Slot。
- 核心工具必须实现独立 `RuntimeSlot` 并经 `platform/modules/ai/tools/register.go` 显式聚合；禁止扫描源码、Go Plugin、隐藏 `init()`，禁止在 ToolService/Agent Runtime 增加业务 Tool ID 分支。
- Action 是否暴露以注册处的 `Metadata.AI` 为唯一事实源；仅 `AIMeta.ExposeTool=true` 自动投影，`AI=nil` 默认不暴露。exposed Action 必须显式声明“动作 + 对象”的 `AIMeta.ToolTitle` 并投影为 `TitleForHuman`，缺失时 fail-closed；禁止按 `Metadata.Name`、SideEffect、Action ID 或模型工具名推导标题。输入使用 `action.InputSchemaFor` 显式声明 required/optional，响应使用 `action.SchemaFor`；HTTP/Tool 复用同一 DTO 和 Handler，Tool Runtime 禁止补字段、修正类型或把局部更新缺失字段解释为清空。Action Tool 只经 `ActionRegistry.Invoke`，禁止维护平行暴露清单。
- MCP Action Adapter 与 Agent 共用 ActionProvider，但独立应用 OAuth scope；`tools/list` 和 `tools/call` 都必须实时复核 realm、permission、scope 与 Action 状态。敏感 Action 需要 sensitive scope 才投影，首次调用返回确认 URL 和 opaque confirmation ID；批准后只允许固定治理工具按 ID 单次恢复，治理工具不得接受 Action ID 或业务参数。外部 MCP Provider 接入 Agent 不属于此适配器。
- Scope 精确 Tool 与来源/能力白名单按“精确命中或来源+能力命中”授权，但 Action 禁止通过精确 Binding 授权，只能命中 Contract 来源+能力；来源/能力只开放渐进 search/load，禁止未 load Schema 进入模型初始投影。
- 新增 Action Tool Capability 时必须同步评估并更新目标 Agent Contract 的来源/能力白名单；测试至少覆盖一个目标 Contract 创建的 Scope 能搜索到该 Action，以及无权限 actor 仍不可见。Action Provider 投影测试不能替代 Scope 可达性测试。
- 同一 Run 的 loaded tools 只能递增；重复 load 只返回紧凑状态，不重复写完整 Schema。Conversation 工作集只表达有界投影偏好，不是授权凭证；显式 Load、新 Scope 恢复和 rehydrate 必须复用统一激活原语并实时重验权限、Contract、动态投影与预算。工作集未命中禁止隐式扩容；Schema 变化时只写配对的中性恢复结果并由主循环基于正式 Schema 重试，禁止执行旧参数。Registry ID 只用于 search/load，执行只接受唯一映射的投影模型名；名称歧义必须 fail-closed。
- Catalog 在模块注册完成、新租户初始化或显式 rebuild 时幂等投影；请求路径禁止写 Catalog。变更以单调 revision 同事务写 Outbox，移除/停用立即 stale，重复/乱序事件不得覆盖当前 Search Document。
- 语义索引只经统一 Embedding Runtime（`purpose=tool_index`）和 Outbox→Job 写 pgvector；Alias、deployment、dimensions、preprocessing、schema/revision 必须匹配。失败自动降级 exact + 中文词法/FTS，混合排序不得先于权限和 Scope 过滤。
- search/load/execute 每次重新应用 tenant、realm、permission、Scope 与启用状态；Embedding/索引绝不是权限事实源。
- Dynamic Reference prerequisite 必须随 search/load 投影但不进入稳定 Schema。`require_evidence` 写调用仅接受同 actor/session/auth version/Scope/Run 的成功 Discovery 摘要证据；缺证据、目录外值在确认前失败且不创建 confirmation，批准后按当前 Resolver 版本和值重校验，失败沿用 consumed/failed 配对 Result 收口。
- Scope 只保存 Resolver ID、Discovery Tool、版本摘要、读取时间和 Invocation ID；禁止保存完整候选。Runtime 只按通用 Dynamic Reference 元数据执行，禁止识别角色等业务 Action ID。
- project/search/load/execute 共用 Slot 动态可用性协议且只能收紧权限；Step/Invocation 分类、专用预算和事实摘要由 Slot 元数据生成，观测只持久化白名单字段。
- Handle 绑定 actor/session/auth version/scope/tool/runtime/schema hash/TTL；任何变化立即失效。
- 写/外部/付费/破坏性/high 必须单次确认，critical 默认禁止；批准后重新鉴权，不支持始终允许。
- 同批 Tool Call 遇确认后停止执行剩余调用并逐个追加 deferred Tool Result；批准、拒绝、过期等确认终态必须保证所有 Tool Call/Result 配对，禁止永久等待。
- Invocation 终态与 Outbox 同事务，日志/Outbox/审计禁止完整参数、结果、Secret 和原始第三方响应。
- Executor Result 必须统一规范化并递归脱敏 typed/untyped JSON 结构；`data + truncation` 共用单一编码字节预算，object/array 裁剪保持类型且数组只保留稳定前缀。通用 Runtime 只报告 returned/omitted 等受控诊断，禁止伪造业务 cursor。
- Tool Call 创建时必须固化 Definition 的 `ToolPresentation`；确认创建事务必须固化版本化 `ConfirmationPresentation`。展示快照只用于解释，禁止作为执行输入；前端禁止解析模型工具名或按 Tool ID 维护业务名称映射。
- 批准必须在短事务中原子认领 confirmation 与 invocation；Executor 在事务外最多执行一次。成功或失败都必须在同一终态事务写 invocation、confirmation=`consumed`、安全 Result 与 finished Outbox；重复决策只返回稳定业务冲突，不得重放或暴露内部状态。
- Agent 恢复必须消费 completed/failed invocation 的配对 Tool Result；可纠正失败只能通过新参数、新 Tool Call 和新逐次确认重试。前端决策期间同时禁用批准/拒绝，并在完成后刷新移除非 pending 卡片。
- 确认文案只能由 Tool Runtime 默认生成器或已注册的可信 Presenter 生成；领域 Presenter 必须租户隔离、权限受控、只读且失败安全降级，Runtime/SSE 禁止按具体 Tool ID 写业务分支或临时查询拼文案。
- `knowledge.search` 必须经 Registry/Scope/Executor，且仅在存在当前可读、enabled、ready 的 Agent 绑定库时投影；知识正文不得进入 Invocation/Step/事件事实摘要。
- 测试统一放在 `platform/tests`。详见 `docs/development/tool-runtime.md`。
- 新增 Action Tool 或 Provider/Executor 时同时遵循 `docs/development/ai-tool-development.md`。
